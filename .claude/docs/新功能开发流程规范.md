# 新功能开发流程规范

> 从一个想法到一个可用功能的完整路径。与 `/dev` 命令同构（命令是本流程的自动化版）。

## 六步流程

```
① 需求澄清 → ② 设计表 → ③ 菜单SQL → ④ 后端六件套 → ⑤ 前端三件 → ⑥ 验证与授权
```

### ① 需求澄清（10 分钟）

回答四个问题：
1. 管什么对象？（→ 表设计）
2. 有哪些字段？哪些是查询条件？（→ Entity + PageParam）
3. 页面什么形态？（普通表格 / 树 / 左树右表 / 主子表）
4. 挂在哪个菜单下？谁能用？（→ SYS_RESOURCE + 角色授权）

### ② 设计表

按数据库设计规范：`BIZ_` 前缀全大写、String 雪花主键、审计字段组、中文 COMMENT。产出 DDL 并执行到 **snowy-cloud** 库。

### ③ 菜单与按钮 SQL

MENU 行（挂到某目录下）+ BUTTON 行（驼峰按钮码）。**这一步常被遗忘**——忘了它，功能再对页面也不显示、按钮全隐藏。

### ④ 后端六件套

两种方式二选一，代码都落在 `snowy-plugin/snowy-plugin-biz/snowy-plugin-biz-func/src/main/java/vip/xiaonuo/biz/modular/{域名}/`：

**方式 A：AI 直写**（`/dev` 默认）——按 crud-development 技能模板逐件生成，先 Read notice 范本再写。

**方式 B：平台代码生成器**——开发工具→代码生成→导入表→填 GenBasic（pluginName=snowy-plugin-biz、moduleName=biz、tablePrefix=Y、busName、className、菜单归属、模板形态）→生成→AI 核对修补（版权头/落位/URL/权限码）。详见 code-generator 技能。

微服务补充：只有当该功能需要被**其他服务**调用时，才额外补 biz-api 接口 + provider + feign 三件并改应用 pom 装配（见 crud-development 技能）；只给前端用的功能不需要。

### ⑤ 前端三件

`api/biz/biz{Xxx}Api.js` + `views/biz/{域名}/index.vue` + `form.vue`（可选 detail.vue）。按 frontend-pc 技能模板。接口统一用 `/biz/` 前缀，`src/utils/apiAdaptive.js` 会自动转到网关的 `/api/bizapp`；域名不要取 sys/auth/client/dev/gen/mobile（会被误映射到 `/api/webapp`）。

### ⑥ 验证与授权（本项目无自动化测试基建，验证 = 启动手测）

```
1. 重启 snowy-biz-app（新代码在 biz-func 里）；改了网关白名单要重启网关，改了服务白名单要重启对应服务
2. 前端刷新（npm run dev 热更通常够，路由变了强刷；前端 9000，经网关 9003 访问后端）
3. 系统管理 → 角色管理 → 给测试角色"授权资源"（新菜单和按钮）+"授权权限"（/biz/{域名}/* 接口；手写接口连超管角色也要授）
4. 用该角色账号登录（或让超管重新授权后重新登录——权限码缓存在 TokenSession）
5. 页面走查：新增 → 列表 → 查询 → 编辑 → 删除 → 详情
6. 接口层验证：http://localhost:9003/doc.html（网关聚合，snowyAdmin/Snowy@2026!，SNOWY-PLUGIN-BIZ 分组）带调（边界值/必填校验/权限）
7. /check 规范检查
```

> ⚠️ 注意（推导，使用前请先确认）："授权权限"弹窗的接口清单来自 Redis 缓存键 `permission-resource`，web-app 与 biz-app 启动时都会整体覆盖它；弹窗里找不到 `/biz/...` 新接口时，先重启 biz-app 再打开。

## 无测试基建下的质量保障

项目仅有两个空壳测试类，**不要试图补测试基建**（引入测试体系属框架改动）。质量保障靠：
1. 六件套模板一致性（生成器模板 = 官方规范）
2. `/check` + code-reviewer 静态审查
3. Knife4j 手测清单（上节第 6 步）
4. 提交前 git-workflow 四原则

## 完成后的收尾

- [ ] DDL 增量脚本存档 `snowy-modules/snowy-web-app/src/main/resources/_sql/`
- [ ] `/update-status` 记录进度
- [ ] commit（`feat: xxx`）
- [ ] 有后续想法 → `/add-todo`

## 常见流程错误

| 错误 | 后果 |
|---|---|
| 忘执行菜单 SQL | 页面不出现 |
| 忘角色授权（授权资源 / 授权权限） | 403 / 按钮全隐 |
| 改白名单没重启，或只改了网关/服务其中一处 | 白名单不生效，另一层仍拦截 |
| 授权后没重新登录 | 权限码是旧的 |
| 表没审计字段 | 自动填充报错/逻辑删除失效 |
| 直接改平台插件实现功能 | 升级即冲突，业务代码进 biz |
| 新代码写完只重启了 web-app | biz 接口 404（biz-func 只在 biz-app 里） |
| 前端 URL 前缀没被 apiAdaptive.js 映射 | 经网关 404 |
| 把定时任务 Runner 写在 biz-func | 配置任务时报"定时任务找不到对应的类" |
