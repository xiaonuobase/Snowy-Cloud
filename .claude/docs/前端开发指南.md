# 前端开发指南（snowy-admin-web）

> Vue 3.5 + Ant Design Vue 4.2.6 + Pinia + vue-i18n，**JavaScript 不是 TypeScript**。范本：`src/views/biz/notice/` + `src/api/biz/bizNoticeApi.js`。完整模板见 `.claude/skills/frontend-pc`。

## 工程约定

- 组件与 Vue API 自动导入（unplugin）：`a-button`、`ref`、`computed` 等不写 import
- 自定义组件 kebab-case 标签（`<s-table>`、`<xn-form-container>`、`<dict-select>`）
- 缩进 **Tab**（Prettier 已配置）
- 命令：`npm install` → `npm run dev`（9000 端口；业务请求由 baseRequest 拼成网关绝对地址 `http://localhost:9003/api/{webapp|bizapp}/...` 直接请求网关，上传/WebSocket 走 vite `/api` 代理到网关 9003）
- 微服务开关：`src/config/index.js` 的 `CLOUD_SERVER: true`；网关前缀映射在 `src/utils/apiAdaptive.js`（详见下文「微服务请求链路」）

## API 封装（bizNoticeApi.js 范本）

```js
import { baseRequest } from '@/utils/request'

const request = (url, ...arg) => baseRequest(`/biz/notice/` + url, ...arg)

export default {
	noticePage(data) {
		return request('page', data, 'get')
	},
	noticeSubmitForm(data, edit = false) {
		return request(edit ? 'edit' : 'add', data)
	},
	noticeDelete(data) {
		return request('delete', data)
	},
	noticeDetail(data) {
		return request('detail', data, 'get')
	}
}
```

第三参是 method（默认 POST）。下载：`baseRequest(url, data, 'get', { responseType: 'blob' })`。URL 只写后端原始路径（`/biz/notice/`），**不要手写 `/api/bizapp` 前缀**（convertUrl 会再拼一次）。

## 微服务请求链路（与单体版最大的不同）

| 环节 | 实际行为 |
|---|---|
| 前缀映射 | `apiAdaptive.js`：`/mobile/` `/sys/` `/auth/` `/client/` `/dev/` `/gen/` → `/api/webapp`；`/biz/` → `/api/bizapp`；`bizCustomization` 数组拼在其后 |
| 匹配规则 | `indexOf` **包含匹配**，按顺序**取第一个命中**；都不命中原样返回 |
| 普通请求 | `baseRequest` 拼 `API_URL + convertUrl(url)` 成绝对地址，直接跨域请求网关 9003（不经 vite 代理） |
| 上传 / WebSocket | `getApiBaseUrl()`（开发环境为 `/api`）+ `convertUrl(...)`，经 vite `/api` 代理去前缀后转发到网关 |
| `.env.*` | `VITE_API_BASEURL = http://localhost:9003`、`VITE_PORT = 9000`（生产需改为真实网关地址） |
| 网关 | `/api/webapp/**` → snowy-web-app、`/api/bizapp/**` → snowy-biz-app（StripPrefix=2） |

新业务模块：沿用 `/biz/` 前缀无需改前端映射；**新 URL 前缀**必须在 apiAdaptive.js 登记，否则经网关 404；新建服务时另加网关路由，新代码包时另加 springdoc 分组与 Knife4j 聚合（只影响接口文档）。biz 业务域名不要取 mobile/sys/auth/client/dev/gen（包含匹配会先命中被发到 web-app）。

## 列表页（index.vue）四区域

```
① 搜索区（a-form inline + 查询条件控件）
② 工具栏（#operator 插槽：新增/批量删除按钮，hasPerm 控制）
③ 表格（s-table :data="loadData"，#bodyCell 自定义列）
④ 弹窗（<form ref="formRef" />，formRef.onOpen(record) 打开）
```

核心机制：
```js
const loadData = (parameter) => {
	const searchFormParam = cloneDeep(searchFormState.value)
	if (searchFormParam.createTime) {                     // 时间范围拆分
		searchFormParam.startCreateTime = searchFormParam.createTime[0]
		searchFormParam.endCreateTime = searchFormParam.createTime[1]
		delete searchFormParam.createTime
	}
	return bizNoticeApi.noticePage(Object.assign(parameter, searchFormParam)).then((data) => data)
}
// 刷新：tableRef.value.refresh(true)；批量删后：clearRefreshSelected()
```

## 弹窗表单（form.vue）要点

- 容器 `xn-form-container`（title 区分新增/编辑：`formData.id ? '编辑' : '增加'`）
- `onOpen(record)`：record 有值编辑（cloneDeep 拷贝）、无值新增（设默认值）
- 校验：`formRules = { name: [required('请输入名称')] }`（formRules.js 的工厂）
- 提交：`formRef.value.validate()` → api → `onClose()` + `emit('successful')`
- **必须 `defineExpose({ onOpen })`**
- 多选字段提交前 JSON.stringify、回显时 JSON.parse（参考 notice 的 place）

## 与后端联调注意

1. 登录密码是 SM2 密文上送（smCrypto.js）——抓包看到 160 位十六进制是正常的
2. id 是字符串——不要 parseInt
3. 接口 401 → token 头没带或过期；403 → 后端资源没授权；⚠️ 经网关时非超管访问超管接口可能返回 500 而非 403（网关已知缺陷）
4. 接口 404 → 先看请求地址有没有 `/api/webapp` 或 `/api/bizapp` 前缀、apiAdaptive 是否登记、网关是否有对应路由
5. 新菜单要 SYS_RESOURCE 有记录 + 角色授权后才显示
6. 接口文档看网关聚合 `http://localhost:9003/doc.html`（basic 认证 snowyAdmin/Snowy@2026!）
