## Maven 模块拓扑

```
snowy-cloud（根 pom）
├── snowy-base/
│   └── snowy-common                 公共基础：统一返回/异常/实体基类/缓存/国密/工具/注解/FeignConstant
├── snowy-plugin/                    插件（8 个），每个插件拆子模块
│   ├── snowy-plugin-sys             B端系统功能        ─┐
│   ├── snowy-plugin-auth            登录鉴权            │ 各含 -api / -func / -feign /
│   ├── snowy-plugin-dev             开发工具            │ -feign-provider / -api-context
│   ├── snowy-plugin-mobile          移动端管理          │
│   ├── snowy-plugin-biz             ★ 业务插件（二开主战场，代码在 -func）─┘
│   ├── snowy-plugin-gen             代码生成器（-api / -func）
│   ├── snowy-plugin-client          C端功能（-api / -func）
│   └── snowy-plugin-mocker          模拟 token（-token-api / -token-func，默认未装配）
├── snowy-modules/                   业务应用（启动模块）
│   ├── snowy-web-app                主应用 9101：装 sys/auth/dev/gen/client/mobile 实现 + 对外 feign-provider
│   └── snowy-biz-app                业务应用 9102：装 biz 实现 + sys/dev/mobile/auth 的远程代理
└── snowy-server/                    中间件应用
    ├── snowy-nacos-app              注册/配置中心 8848
    ├── snowy-gateway-app            网关 9003
    ├── snowy-actuator-app           Spring Boot Admin 9001
    ├── snowy-sentinel-app           Sentinel 控制台 9002
    └── snowy-xxl-job-app            xxl-job 调度中心 9004
```

依赖规则：插件实现（-func）不互依赖；跨插件通信走 `*-api` 接口 + 对方 `provider/` 实现（返回 hutool JSONObject）。同服务内本地注入；跨服务时由 `-api-context`（调用方代理）→ `-feign`（Feign 接口）→ `-feign-provider`（被调方服务端）→ provider 完成，业务代码仍只注入 `XxxApi`。同一应用里某插件要么装 -func，要么装 -feign + -api-context，不能同装。详见 `.claude/skills/plugin-architecture`。

## 模块间真实调用地图（提取自各插件 -func 的 pom 与应用装配）

A→B = A 的 -func 依赖 B 的 `*-api`：

| 调用方（所在服务） | 依赖的 api | 调用方式 | 典型用途 |
|---|---|---|---|
| biz（biz-app） | sys-api、auth-api、dev-api | 跨服务（ContextBean → Feign → web-app） | 业务要用户/登录态（SaBaseLoginUser）/配置文件消息 |
| auth（web-app） | sys-api、dev-api、client-api | 同服务本地 | 登录验用户取权限、发验证码（短信/邮件）、C 端用户 |
| sys（web-app） | auth-api、dev-api、mobile-api | 同服务本地 | 登录用户 POJO/在线 token 操作、字典翻译、移动端按钮码 |
| dev（web-app） | sys-api、auth-api | 同服务本地 | 日志关联用户、监听器用户类型 |
| mobile（web-app） | auth-api、dev-api、sys-api | 同服务本地 | 移动资源管理引用用户/字典 |
| client（web-app） | auth-api、dev-api | 同服务本地 | C 端登录态与工具能力 |
| gen（web-app） | sys-api、mobile-api | 同服务本地 | 生成时读模块/菜单挂载点、写移动端资源 |

**关键理解**：sys↔dev、auth↔sys 出现"互相调用"，但**实现层零循环**——互相依赖的只是对方的 api 接口模块。web-app 内与单体版一样同 JVM 注入；出厂真正跨服务的只有 biz-app → web-app 方向（biz 插件另有 web-app → biz-app 的"机构主管转移"Feign 三件，但默认未装配）。

四条典型调用链：

1. **登录链**：前端 → 网关 `/api/webapp/auth/b/doLogin` → web-app AuthServiceImpl（SM2 解密 + SM3 比对）→ `loginUserApi.getUserByAccount()`（落到同服务的 SysLoginUserApiProvider）→ 组装 permissionCodeList（数据范围 apiUrl）+ buttonCodeList → StpUtil.login → token 下发；会话存 Redis，网关与 biz-app 从同一 Redis 读取 loginUser 做鉴权
2. **业务发通知**：biz-app 注入 DevMessageApi → DevMessaeApiContextBean → DevMessageFeign → web-app DevMessageFeignProvider → dev 落 DEV_MESSAGE → WebSocket 实时推前端消息中心
3. **共享数据联动（反向通知，零依赖）**：发布方 Service 调 `CommonDataChangeEventCenter.doUpdateWithData` 广播（snowy-common）→ 本服务内的监听器处理；⚠️ 事件中心是进程内列表，不跨服务（web-app 里 sys 的变更，biz-app 的监听器收不到）
4. **代码生成**：gen（web-app）读 sys-api 模块/菜单 → Beetl 渲染六件套 + 前端 + sqlend → 写到 `snowy-plugin/{插件}/{插件}-func` 与 `snowy-admin-web/src`，产出 SYS_RESOURCE/MOBILE_RESOURCE INSERT；不生成 feign/api-context，不改网关与 apiAdaptive.js

接口资产：sys-api 11 个、dev-api 12 个、auth-api（AuthApi/AuthInnerApi/SaBaseLoginUserApi + SaBaseLoginUser 等 POJO + StpLoginUserUtil 等工具）、biz-api 6 个、mobile-api 4 个、client-api 1 个（ClientUserApi 在 `vip.xiaonuo.client` 包根）、gen-api 空壳。
biz-app 可用的远程代理：sys 8 个（缺 Menu/Button/Module）、dev 7 个（缺 Dict/Log/Job/Push/WeakPassword）、auth 全部、mobile 全部；缺的接口按现有装配方式在 biz-app 注入会缺 Bean，使用前请先确认。

## 启动链路

```
SnowyNacosApp（snowy-nacos-app，8848）
  ← 配置存 MySQL snowy-nacos-app-open；仓库源文件 META-INF/config-data/{dev,test,prod}/，初始化 SQL nacos-db.sql（建表 + 全部配置；nacos-db-snowy-config-init.sql 仅用于刷新已有库的配置）
SnowyWebApp（snowy-web-app，9101） / SnowyBizApp（snowy-biz-app，9102）
  ← @EnableDiscoveryClient + @EnableFeignClients(basePackages = "vip.xiaonuo") + scanBasePackages = "vip.xiaonuo"
  ← 本地 application.yml：只做 Nacos 接入（namespace snowy-cloud-dev、group dev、dataId {应用名}-dev.yaml，nacos/nacos）
  ← Nacos 配置：端口/数据源(master，库 snowy-cloud)/Redis(6379 db1)/Sa-Token(token 名 token，30天)/springdoc 分组/国密密钥
  ← GlobalConfigure：@MapperScan("vip.xiaonuo.**.mapper")、SaServletFilter 路由鉴权（白名单三段，路径不带前缀）/分页插件/审计字段自动填充/防重AOP/返回包装AOP/数据变更监听注册
  ← GlobalExceptionHandler：全局异常 → CommonResult
  ← FeignRequestInterceptor：Feign 调用透传全部请求头 + traceId
SnowyGatewayApp（snowy-gateway-app，9003）
  ← 路由：/api/webapp/** → lb://snowy-web-app、/api/bizapp/** → lb://snowy-biz-app（StripPrefix=2）、/druid/** → web-app
  ← GatewayConfigure：SaReactorFilter 鉴权（白名单三段，路径带 /api/webapp、/api/bizapp 前缀）
  ← CorsFilter 跨域；Sentinel 限流；Knife4j 聚合 /doc.html（basic 认证 snowyAdmin/Snowy@2026!）
```

接口文档分组：AUTH/DEV/GEN/MOBILE/SYS 在 web-app 的 springdoc 配置，BIZ/CLIENT 在 biz-app 的 springdoc 配置，由网关 Knife4j 聚合；各服务自身 knife4j.basic.enable=false。

前端：`snowy-admin-web`，`npm run dev` 起 9000 端口；`apiAdaptive.js` 给 URL 加网关前缀，`request.js` 拼成 `VITE_API_BASEURL`（http://localhost:9003）+ 前缀 + URL 直连网关。

## B/C 双端模型

| | B 端 | C 端 |
|---|---|---|
| 用户 | SYS_USER | CLIENT_USER |
| 登录 | /auth/b/*（经网关 /api/webapp/auth/b/*） | /auth/c/*（经网关 /api/webapp/auth/c/*） |
| 业务接口 | /sys/* /dev/* /gen/*（web-app）、/biz/*（biz-app，经网关 /api/bizapp/biz/*） | /client/c/*（web-app） |
| 工具 | StpUtil / StpLoginUserUtil | StpClientUtil / StpClientLoginUserUtil |

鉴权细节见 `.claude/skills/security-auth`。白名单两层都生效：网关 GatewayConfigure（带前缀）+ 服务 GlobalConfigure（不带前缀）。

## 权限体系（两层）

1. **接口权限**：`@SaCheckPermission("/url")` — 用户角色授权资源后生成的 apiUrl 列表；URL 为服务内路径（不带网关前缀）
2. **按钮权限**：SYS_RESOURCE BUTTON 行的驼峰码 — 前端 `hasPerm('bizXxxAdd')`
